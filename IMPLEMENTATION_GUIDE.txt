MONITORING & TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

CHECK LOGS:
───────────────────────────────────────────────────────────────────────────────
# PHP-FPM logs
docker-compose logs -f app1

# Nginx logs
docker-compose logs -f nginx-lb

# Check for ETag middleware activity (local env only)
docker-compose exec app1 tail -f storage/logs/laravel.log | grep ETag

VERIFY CONFIGURATIONS:
───────────────────────────────────────────────────────────────────────────────
# Check nginx HTTP/2
docker-compose exec nginx-lb nginx -T | grep "listen.*http2"

# Check PHP-FPM settings
docker-compose exec app1 cat /usr/local/etc/php-fpm.d/www.conf | grep "pm\."

# Check Redis persistence
docker-compose exec redis-master redis-cli CONFIG GET "*persistent*"

COMMON ISSUES:
───────────────────────────────────────────────────────────────────────────────
1. Migration fails "index already exists"
   → Normal if re-running, indexes are safe to skip

2. HTTP/2 not working
   → Ensure SSL is configured or use HTTP/1.1 for local dev

3. Cache warming fails
   → Check APP_URL in .env matches your setup
   → Ensure database has data to warm

4. ETags not generating
   → Check middleware is registered in Kernel.php
   → Verify response is 200 OK on GET requests

ROLLBACK PROCEDURE (If needed)
═══════════════════════════════════════════════════════════════════════════════

If you need to revert changes:

1. Rollback migration:
   docker-compose exec app1 php artisan migrate:rollback --step=1

2. Restore previous configs:
   - docker/nginx/default.conf (change http2 back to normal)
   - docker/php/www-optimized.conf (restore old pm values)
   - src/app/Http/Kernel.php (restore old middleware array)
   - src/config/database.php (remove persistent settings)

3. Rebuild containers:
   docker-compose down
   docker-compose build --no-cache
   docker-compose up -d
