5. ETAG SUPPORT
   Effort: 15-20 minutes
   Impact: 50-80% bandwidth reduction for unchanged resources
   
   Implementation:
   - Add ETag middleware to generate hash of response content
   - Return 304 Not Modified if client's If-None-Match matches
   
   Laravel implementation:
   ```php
   // Create middleware: app/Http/Middleware/ETagMiddleware.php
   public function handle($request, Closure $next)
   {
       $response = $next($request);
       
       if ($response->isSuccessful()) {
           $etag = md5($response->getContent());
           $response->header('ETag', $etag);
           
           if ($request->header('If-None-Match') === $etag) {
               return response('', 304);
           }
       }
       
       return $response;
   }
   ```
   
   Register in Kernel.php:
   'api' => [
       \App\Http\Middleware\ETagMiddleware::class,
   ]
   
   Benefit:
   - Massive bandwidth savings (50-80%)
   - Faster response times for unchanged data
   - Reduced server load
   - Better mobile experience

6. QUERY RESULT CACHING
   Effort: 20-30 minutes
   Impact: 20-30% faster first loads (non-cached JSON responses)
   
   Current: Only JSON responses are cached
   Improvement: Cache raw database query results separately
   
   Implementation:
   ```php
   // In CourseController
   public function get($id)
   {
       // Cache raw query result (separate from JSON)
       $course = Cache::remember("course_query_{$id}", 3600, function() use ($id) {
           return Course::with(['modules.lessons.epubs'])
               ->select('id', 'title', 'description', 'isOpen')
               ->findOrFail($id);
       });
       
       // Then cache JSON separately (already implemented)
       return Cache::remember("course_json_{$id}_v2", 3600, function() use ($course) {
           // Transform to array...
       });
   }
   ```
   
   Benefit:
   - Two-layer caching strategy
   - Faster JSON regeneration if needed
   - Reduced database queries
   - Better cache hit rates

7. CACHE PRELOADING ON DEPLOYMENT
   Effort: 15 minutes
   Impact: Consistent 260ms response times (no cold starts)
   
   Create script: warm_cache.php
   ```php
   <?php
   // Warm up critical cache entries after deployment
   
   require __DIR__.'/vendor/autoload.php';
   $app = require_once __DIR__.'/bootstrap/app.php';
   
   echo "Warming cache...\n";
   
   // Warm course list
   $response = $app->make('request')->create('/api/courses', 'GET');
   $app->handle($response);
   echo "✓ Course list cached\n";
   
   // Warm individual courses
   $courses = DB::table('courses')->pluck('id');
   foreach ($courses as $courseId) {
       $response = $app->make('request')->create("/api/courses/{$courseId}", 'GET');
       $app->handle($response);
       echo "✓ Course {$courseId} cached\n";
   }
   
   echo "Cache warming complete!\n";
   ```
   
   Add to deployment script:
   php warm_cache.php
   
   Benefit:
   - No cold starts for users
   - Consistent fast response times
   - Better user experience after deployment

8. BROTLI COMPRESSION
   Effort: 30-45 minutes
   Impact: 10-15% faster transfers (15-20% smaller payloads vs gzip)
   
   Steps:
   1. Install ngx_brotli module in nginx Dockerfile
   2. Update nginx configuration
   
   Configuration:
   ```nginx
   brotli on;
   brotli_comp_level 6;
   brotli_static on;
   brotli_types application/json text/plain text/css application/javascript;
   brotli_min_length 256;
   
   # Keep gzip as fallback
   gzip on;
   gzip_vary on;
   ```
   
   Benefit:
   - Better compression ratio than gzip
   - Especially effective for JSON APIs
   - Modern browser support
   - Automatic fallback to gzip

9. REDIS CONNECTION POOLING
   Effort: 10-15 minutes
   Impact: 5-10% faster cache operations
   
   Location: config/database.php
   
   Current:
   'redis' => [
       'client' => env('REDIS_CLIENT', 'phpredis'),
       'default' => [
           'host' => env('REDIS_HOST', '127.0.0.1'),

       'client' => env('REDIS_CLIENT', 'phpredis'),

           'timeout' => 2.0,
           'read_timeout' => 2.0,

   Benefit:

10. CURSOR-BASED PAGINATION
    Effort: 30-40 minutes
    Impact: Better performance for large datasets
    
    Current: Offset pagination (LIMIT/OFFSET)
    Problem: Slow for large offsets (SELECT * FROM courses LIMIT 10000, 10)
    
    Solution: Cursor-based pagination
    ```php
    // In CourseController
    public function getList(Request $request)
    {
        $cursor = $request->get('cursor');
        
        $query = Course::select('id', 'title', 'description')
            ->orderBy('id');
        
        if ($cursor) {
            $query->where('id', '>', $cursor);
        }
        
        $courses = $query->limit(10)->get();
        
        return response()->json([
            'data' => $courses,
            'next_cursor' => $courses->last()?->id,
            'has_more' => $courses->count() === 10,
        ]);
    }
    ```
    
    Benefit:
    - Constant time complexity O(1) vs O(n) for offset
    - Scales to millions of records
    - Consistent performance regardless of page number
